# Implementation Plan: Kafka Search Event Consumer

**Branch**: `001-kafka-event-consumer` | **Date**: 2026-06-07 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-kafka-event-consumer/spec.md`

---

## Summary

Build a Spring Boot 4 / Kotlin 2.4 backend service that consumes user-search events from
Kafka topics, validates and persists them to PostgreSQL, enforces idempotency, maintains
a full processing audit trail, and exposes health, readiness, and audit-query REST endpoints.
The service follows Clean Onion (Hexagonal) Architecture with strict layer isolation.
All infrastructure interactions (Kafka, PostgreSQL) use real integration tests via Testcontainers.

---

## Technical Context

**Language/Version**: Kotlin 2.4.0 on JVM 21 (LTS)

**Primary Dependencies**:
- Spring Boot 4.0.6 (Spring Framework 7.x, Jakarta EE 11)
- Spring Kafka 4.x (`spring-kafka`)
- Spring Data JPA + Hibernate 7.x
- Flyway 11.x (Spring Boot managed)
- Micrometer 1.14+ with Prometheus registry
- Spring Boot Actuator
- Logback + `logstash-logback-encoder` 8.x
- Jackson 2.18+ (`jackson-module-kotlin`)
- Jakarta Validation 3.x

**Storage**: PostgreSQL 16 (primary). JSONB columns for flexible schema fields.

**Testing**: JUnit 5, MockK 1.13+, Spring Boot Test, Testcontainers 1.20+
(Kafka + PostgreSQL containers)

**Target Platform**: Linux container (JVM 21). Kubernetes deployment. `linux/amd64`.

**Project Type**: Single event-consumer service (web-service with Kafka inbound adapter)

**Performance Goals**:
- Throughput: ≥ 500 events/s on a single instance (SC-PERF-002)
- p99 end-to-end latency (Kafka publish → DB commit): ≤ 500 ms (SC-PERF-001)

**Constraints**:
- Memory ceiling: ≤ 512 MB resident (constitution Performance Benchmarks)
- At-least-once delivery: Kafka offset NOT committed before DB write confirmed (FR-010)
- Idempotent inserts: unique constraint on `search_records.event_id`
- No DLQ Kafka topic in v1; dead-lettered events land in audit log only

**Scale/Scope**:
- Single consumer group; partition-level concurrency
- Single PostgreSQL instance (connection pool via HikariCP)
- Multi-topic support via configurable topic list

## Functional Requirements Analysis

| FR | Implementation Approach |
|---|---|
| FR-001: Consume from configurable topics | `@KafkaListener(topics = ["#{@kafkaTopics}"])` — topic list from `application.yml` |
| FR-002: Validate events | Jackson deserialization + JSON Schema validation (NetworkNt or custom validator) in `KafkaSearchEventListener` before calling use case |
| FR-003: Persist with original timestamp | `TIMESTAMPTZ` column; `OffsetDateTime` mapped via Hibernate; no normalisation |
| FR-004: Idempotency | Unique constraint on `event_id`; catch `DataIntegrityViolationException` → audit DUPLICATE |
| FR-005: Malformed events logged, skipped | `DefaultErrorHandler` + domain validation; ERROR log with MDC; audit REJECTED; `Acknowledgment.acknowledge()` called regardless |
| FR-006: Audit trail | `EventAuditLog` written in separate transaction for every processing attempt |
| FR-007: Health/readiness endpoints | Spring Boot Actuator + custom `KafkaHealthIndicator` |
| FR-008: Operational metrics | Micrometer counters + timer in `SearchEventProcessorService`; consumer lag via `KafkaMetrics` binder |
| FR-009: Auto-recovery | `DefaultErrorHandler(ExponentialBackOffWithMaxRetries)`; Spring Kafka reconnect on broker unavailability |
| FR-010: Offset after DB write | `AckMode.MANUAL_IMMEDIATE`; `Acknowledgment.acknowledge()` called only after successful transaction commit |
| FR-011: Schema extensibility | `additionalProperties: true` in JSON Schema; Jackson `@JsonAnySetter`; `extra_fields JSONB` column |
| FR-012: Structured logging with correlation_id | MDC.put("correlation_id", eventId) in listener; logstash-logback-encoder serialises MDC |

## Domain Model Design

See [data-model.md](data-model.md) for the full domain class map, value objects, and
entity specifications.

**Key design decisions**:
- `SearchRecord` is an immutable aggregate root — no state mutations after creation.
- `EventAuditLog` is a separate entity, not part of `SearchRecord` aggregate — written
  independently to allow audit records even when `SearchRecord` creation fails.
- Domain layer contains zero Spring or JPA annotations. Dependency rule strictly enforced.
- `ProcessingStatus` is a sealed-interface-backed enum for exhaustive `when` expressions.

---

## Database Schema Design

See [data-model.md](data-model.md) for full DDL.

**Key decisions**:
- `TIMESTAMPTZ` (not `TIMESTAMP`) for all timestamp columns — preserves timezone offset.
- `JSONB` for `search_criteria`, `search_result`, and `extra_fields` — queryable,
  indexable, schema-flexible.
- `UNIQUE(event_id)` on `search_records` as the idempotency enforcement mechanism.
- `partition_num` (not `partition`) to avoid PostgreSQL reserved word conflict.
- GIN index on `search_criteria` enables analytics queries like
  `WHERE search_criteria @> '{"cabin_class":"BUSINESS"}'`.

## Service Layer Design

### `SearchEventProcessorService` (application service, implements `ProcessSearchEventUseCase`)

```
processEvent(message: SearchEventMessage, acknowledgment: Acknowledgment):
  1. Map message → domain command
  2. Validate required fields (domain validation)
  3. If invalid → auditLogRepository.save(REJECTED) → acknowledge → return
  4. Begin transaction
  5. Try searchRecordRepository.save(SearchRecord)
     On DataIntegrityViolationException (duplicate):
       → auditLogRepository.save(DUPLICATE) → acknowledge → return
  6. auditLogRepository.save(PROCESSED)
  7. Commit transaction
  8. acknowledge offset
  9. Publish domain event SearchEventReceived (optional, future extension)
  10. Update Micrometer counters
```

**Transaction boundary**: Steps 5–7 are within a single `@Transactional` block. If the
transaction fails, no `PROCESSED` audit row is written, and the offset is NOT acknowledged —
triggering redelivery.

**Error handler**: `DefaultErrorHandler` with `ExponentialBackOffWithMaxRetries(5)` handles
transient DB errors (not `DataIntegrityViolationException`). After max retries:
→ `auditLogRepository.save(DEAD_LETTERED)` → acknowledge (to prevent consumer stall).

### `AuditLogQueryService` (application service, implements `QueryAuditLogUseCase`)

Read-only service. Delegates to `AuditLogRepository` outbound port. No transaction needed
(read-only queries use `@Transactional(readOnly = true)`).

## Repository Design

### Outbound Ports (interfaces in `application/port/outbound/`)

```kotlin
interface SearchRecordRepository {
    fun save(record: SearchRecord): SearchRecord
    fun existsByEventId(eventId: EventId): Boolean
}

interface AuditLogRepository {
    fun save(entry: EventAuditLog): EventAuditLog
    fun findByEventId(eventId: String): List<EventAuditLog>
    fun findAll(filter: AuditLogFilter, pageable: Pageable): Page<EventAuditLog>
    fun findById(id: UUID): EventAuditLog?
}
```

### Persistence Adapters (in `adapter/outbound/persistence/`)

`SearchRecordPersistenceAdapter` implements `SearchRecordRepository`:
- Maps `SearchRecord` domain object → `SearchRecordJpaEntity` via `SearchRecordMapper`
- Calls `SearchRecordJpaRepository.save()` (Spring Data JPA)
- Maps result back to domain object

`AuditLogPersistenceAdapter` implements `AuditLogRepository`:
- Same mapper pattern
- Query methods use Spring Data JPA derived queries + `@Query` for complex filters

**JPA entities** live only in `adapter/outbound/persistence/` — the domain layer never
sees `@Entity`, `@Column`, etc.

## Validation Strategy

**Layer 1 — Structural validation** (in `KafkaSearchEventListener`):
- Jackson deserialization: fails on invalid JSON → REJECTED
- JSON Schema validation against `search-event-v1.json` contract: fails on missing required
  fields or type mismatches → REJECTED

**Layer 2 — Domain validation** (in `SearchEventProcessorService` / domain):
- `EventId` value object constructor validates UUID format
- `event_timestamp` parsed to `OffsetDateTime` — fails on invalid ISO-8601 → REJECTED
- Business invariants (e.g. `user_id` not blank) checked in domain model constructor

**REST layer** (audit log query endpoint):
- Jakarta Validation on `@RequestParam` (e.g. `@Min(0) page`, `@Max(100) size`)
- `@ControllerAdvice` catches `MethodArgumentNotValidException` → `ProblemDetail` 400

## Error Handling Strategy

| Scenario | Handling | Outcome |
|---|---|---|
| Invalid JSON | Deserialization error → catch in listener | REJECTED audit, offset acked, consumer continues |
| Missing required fields | JSON Schema validation failure | REJECTED audit, offset acked, consumer continues |
| Duplicate event_id | `DataIntegrityViolationException` | DUPLICATE audit, offset acked, no DB record |
| Transient DB error | `DefaultErrorHandler` + exponential back-off (5 retries) | RETRY audit rows, then PROCESSED or DEAD_LETTERED |
| DB unavailable at startup | `HealthIndicator` → not-ready; Kafka listener not started until DB ready | No event consumption during outage |
| Kafka unavailable at startup | Spring Kafka auto-reconnect; `HealthIndicator` → not-ready | Reconnects with back-off; no data loss |
| Max retries exceeded | `DeadLetterPublishingRecoverer` replaced by DEAD_LETTERED audit write + metric alert | Consumer continues |
| REST validation failure | Jakarta Validation → `@ControllerAdvice` → `ProblemDetail` 400 | Standard RFC 7807 error response |
| Unexpected exception | `@ControllerAdvice` global handler → `ProblemDetail` 500 | Internal error, no stack trace exposed |

## Risks and Edge Cases

| Risk | Mitigation |
|---|---|
| Kafka offset commit race (DB commit succeeds, offset commit fails) | Unique constraint on `event_id` prevents duplicate row on redelivery. Audit log records re-attempt as DUPLICATE. |
| Consumer lag accumulation during DB outage | Kafka retains messages per configured retention. Partition count sized for catch-up throughput. Monitor `consumer_lag` metric. |
| JSONB query performance at scale | GIN index on `search_criteria`. JSONB columns bounded by Postgres row size limit (1 GB, not a practical concern). |
| Schema version mismatch (source system changes event_id to non-UUID) | `EventId` value object catches format errors → REJECTED. Monitor rejection rate metric for anomaly detection. |
| HikariCP pool exhaustion under burst load | Pool sized to `concurrency × 2`. Max pool size configurable. `connectionTimeout` set to 3 s to fail fast rather than queue. |
| Testcontainers slow CI | Cache container images in CI. Use `@TestcontainersConfiguration` with `@Container` reuse across test class. |
| Memory pressure from large JSONB payloads | `rawPayloadRef` in audit log truncated to 500 chars. `extra_fields` serialisation bounded by Jackson max string length config. |
